## ユーザーシナリオとテスト（必須）

### ユーザーストーリー 1 — GUI でネコチャン絵文字の提案を受け取る（優先度: P1）

ユーザーが `nekochan-suggest-ui` コマンドを実行するとブラウザが開き、
テキスト入力欄に文章を入力して「提案する」ボタンを押すと、
その文章に合ったネコチャン絵文字の候補が名前・スコア・画像とともに画面に表示される。
CLI に不慣れなユーザーやビジュアルで絵文字を選びたいユーザーのために
グラフィカルなインターフェースを提供する。

**この優先度の理由**: このフィーチャーの核心的な価値であり、これ単体で完結する MVP となる。
他のユーザーストーリーはこの基本フローの上に成り立つ。

**独立テスト**: `nekochan-suggest-ui` を実行してブラウザを開き、
「今日もいい天気ですね」と入力して「提案する」をクリックすると、
絵文字名・スコア・画像が表示されれば完結する。

**受け入れシナリオ**:

1. **Given** アノテーションファイルが存在し、`nekochan-suggest-ui` を起動した状態で、
   **When** テキスト入力欄に「今日も頑張ろう！」と入力して「提案する」ボタンをクリックする、
   **Then** 候補が 3 件以上表示され、各候補には絵文字名（例: `yatta-nya`）・
   コサイン類似度スコア（0〜1 の浮動小数点）・絵文字画像が表示される。

2. **Given** アノテーションファイルが存在し、GUI が表示されている状態で、
   **When** 入力欄を空のまま「提案する」ボタンをクリックする、
   **Then** 入力欄に文章を入力するよう促すメッセージが表示され、提案は実行されない。

3. **Given** アノテーションファイルが存在し、一度提案を実行した状態で、
   **When** 別の文章に書き換えて再度「提案する」ボタンをクリックする、
   **Then** 新しい文章に対応した候補が再表示される（前回の結果は上書きされる）。

---

### ユーザーストーリー 2 — アノテーション未構築時のエラー案内を受け取る（優先度: P2）

ユーザーが `nekochan-suggest-ui` を起動したとき、アノテーションファイルが
まだ構築されていない（または見つからない）場合、
GUI 画面にわかりやすいエラーメッセージとセットアップ手順が表示される。

**この優先度の理由**: ツールを初めて使うユーザーが詰まりやすいポイントであり、
適切な案内がなければ CLI に戻って調査が必要になる。エラーが可視化されることで
ユーザーが次のアクションを取れる。

**独立テスト**: アノテーションファイルを存在しない状態で `nekochan-suggest-ui` を起動し、
セットアップを促すエラーメッセージが画面に表示されれば完結する。

**受け入れシナリオ**:

1. **Given** アノテーションファイルが存在しない状態で `nekochan-suggest-ui` を起動した、
   **When** GUI 画面が表示される、
   **Then** 「アノテーションファイルが見つかりません」旨のエラーメッセージと
   `build-annotations` コマンドの実行を促す案内が表示される。

2. **Given** アノテーションファイルが存在しない状態で GUI が表示されている、
   **When** テキスト入力欄に文章を入力して「提案する」ボタンをクリックする、
   **Then** 提案処理は実行されず、エラーメッセージが継続表示される。

---

### エッジケース

- テキスト入力欄が空の場合、提案処理を実行せず入力を促すメッセージを表示する。
- アノテーションファイルは存在するが内容が空（レコード 0 件）の場合、
  提案結果ゼロ件として「候補が見つかりませんでした」旨を表示する。
- ネコチャン画像の URL が到達不能（インターネット未接続など）の場合、
  Streamlit の画像表示が失敗しても候補名とスコアは表示を継続する。
- 入力文章が 1000 文字を超えた場合、超過部分を無視して先頭 1000 文字で提案を実行し、
  文字数制限を超えた旨をメッセージで通知する。
- `suggest()` が例外を発生させた場合（Ollama 未起動・埋め込みモデル未ダウンロードなど）、
  `st.error()` でエラーメッセージを表示し、入力欄は維持する。スタックトレースは表示しない。

## 要件（必須）

### 機能要件

- **FR-001**: `nekochan-suggest-ui` コマンドを実行すると、Streamlit ベースの GUI が
  ブラウザで起動しなければならない。起動には `streamlit.web.cli.main_run()` を使用する。
- **FR-002**: GUI はテキスト入力欄と「提案する」ボタンを提供しなければならない。
- **FR-003**: 「提案する」ボタンを押すと、入力文章に基づいてネコチャン絵文字の候補が
  画面に表示されなければならない。各候補には絵文字ファイル名と類似度スコアを含む。
  候補は縦方向カードレイアウトで表示し、1 候補につき `st.image()` で画像、
  `st.write()` で絵文字名とスコアを縦に並べる。
- **FR-004**: 各候補のネコチャン画像を画面に表示しなければならない。
  画像 URL は `https://raw.githubusercontent.com/takanory/sphinx-nekochan/main/sphinx_nekochan/images/<name>.png`
  のパターンで構築する（インターネット接続が必要）。
- **FR-005**: 提案ロジックは既存の `suggest()` ライブラリ関数を呼び出す形で実装しなければならない。
  GUI 層はビジネスロジックを持たず、表示処理のみを担う。
- **FR-006**: アノテーションファイルが存在しない場合、提案を実行せずに
  エラーメッセージと `build-annotations` コマンドの実行案内を画面に表示しなければならない。
- **FR-007**: テキスト入力欄が空の場合、「提案する」ボタンを押しても提案処理を実行せず、
  文章の入力を促すメッセージを表示しなければならない。
- **FR-008**: 表示する候補件数はデフォルト 3 件とし、既存の `suggest()` 関数の
  `count` パラメータにより制御されるものとする。
- **FR-009**: 「提案する」ボタン押下時に `suggest()` が例外を発生させた場合
  （例: Ollama 未起動、埋め込みモデル未ダウンロード）、`st.error()` で
  ユーザーフレンドリーなエラーメッセージを表示し、テキスト入力欄は維持する。

### スコープ外

- 候補件数のユーザー変更（スライダーや入力欄による件数指定）は本フィーチャーのスコープ外とする。
- 認証・ユーザー管理は不要。
- サーバーへのデプロイ・公開機能はスコープ外。ローカル起動のみを対象とする。

### 前提依存

- 追加 PyPI 依存は `streamlit` のみ。`pyproject.toml` の `[project.optional-dependencies]` に
  `gui = ["streamlit"]` として追加し、`pip install nekochan-suggest[gui]` でインストールする。
- `nekochan_suggest/query.py` の `suggest()` 関数が実装済みであること（`003-emoji-query` で完了）。
- `nekochan-suggest-ui` エントリーポイントが `pyproject.toml` に定義済みであること。

### 主要エンティティ

- **テキスト入力**: ユーザーが提案を求める文章。1 文字以上 1000 文字以下。
- **提案結果**: マッチした絵文字のファイル名とコサイン類似度スコアの組（`SuggestionResult`）のリスト。
- **絵文字画像 URL**: `https://raw.githubusercontent.com/takanory/sphinx-nekochan/main/sphinx_nekochan/images/<name>.png`
  の形式で構築される URL。画像取得にはインターネット接続が必要。

## 成功基準（必須）

### 測定可能な成果

- **SC-001**: `nekochan-suggest-ui` コマンド実行からブラウザで GUI が表示されるまで、
  通常のローカル環境で 10 秒以内に完了する。
- **SC-002**: テキストを入力して「提案する」をクリックしてから提案結果が画面に表示されるまで、
  埋め込みモデルのロード済み状態で 5 秒以内に完了する。
- **SC-003**: GUI 操作のみで（CLI を使わずに）ネコチャン絵文字の提案を受け取る
  一連のタスクを完遂できる。
- **SC-004**: アノテーションファイルが存在しない場合、ユーザーが次に実行すべきコマンドを
  エラーメッセージから把握できる（案内文にコマンド名が明示されている）。

## 前提条件・仮定

- Ollama によるクエリ処理（埋め込み生成）は `suggest()` 関数の内部で完結しており、
  GUI 層が Ollama を直接呼び出すことはない。
- 初回起動時の埋め込みモデルロード時間（数十秒）は許容範囲とし、SC-002 の測定対象外とする。
- `st.image()` に URL を渡す実装方式を採用する。画像の事前キャッシュは行わない。
- GUI のスタイリングや多言語対応はスコープ外とする。日本語のラベル・メッセージを標準とする。
- テストは `suggest()` 等のビジネスロジック関数を `unittest.mock` でモック化する形で実施する。
  Streamlit の UI レンダリング（ウィジェット描画）自体はテスト対象としない。
